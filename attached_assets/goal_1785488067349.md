# Prompt: Convert Existing Custom HTML Theme into a Native Elementor Theme (Without Changing the Design)

## Objective

Convert the existing custom-developed HTML theme (which was originally built from an HTML template and later partially converted into an Elementor-compatible structure) into a **fully native Elementor-based WordPress theme**.

The current implementation uses **HTML widgets containing large chunks of custom HTML**, which makes editing difficult for non-technical users. The goal is to replace those HTML blocks with proper Elementor widgets and containers while **preserving the exact frontend design**.

---

# Important Requirements

## 1. Preserve the Existing UI Completely

This is the highest priority.

- Do NOT redesign anything.
- Do NOT modernize the UI.
- Do NOT improve spacing.
- Do NOT change typography.
- Do NOT change margins.
- Do NOT change paddings.
- Do NOT change alignment.
- Do NOT change animations.
- Do NOT change responsiveness.
- Do NOT change colors.
- Do NOT change border radius.
- Do NOT change shadows.
- Do NOT replace icons.
- Do NOT modify breakpoints.

The final frontend should be **pixel-perfect** compared to the current theme.

Think of this task as converting the implementation—not redesigning the website.

---

# 2. Replace HTML Blocks with Native Elementor Widgets

Currently the Elementor editor looks similar to this:

Section
└── Column
    └── HTML Widget
        └── Entire page HTML

Instead, it should become:

Section
└── Container
    ├── Heading
    ├── Text Editor
    ├── Button
    ├── Image
    ├── Icon
    ├── Icon Box
    ├── Divider
    ├── Spacer
    ├── Video
    ├── Counter
    ├── Progress Bar
    ├── Tabs
    ├── Accordion
    ├── Gallery
    ├── Form
    ├── Loop Grid (if applicable)
    └── Any custom Elementor widget where required

Each visual element should become an editable Elementor widget.

No section should consist of one large HTML widget.

---

# 3. Native Elementor Structure

Use Elementor's latest Container architecture.

Example:

Container
├── Inner Container
│   ├── Heading
│   ├── Text
│   ├── Buttons
│   └── Icons
└── Image

instead of

Container
└── HTML Widget

Every section should be editable using Elementor's native controls.

---

# 4. Preserve Existing CSS

The current CSS has already been tested.

Reuse it wherever possible.

Do not rewrite the styling unless absolutely necessary.

Only create additional CSS when Elementor requires it.

Avoid duplicate styles.

Avoid inline styles whenever possible.

---

# 5. Preserve Existing JavaScript

Keep all existing:

- animations
- sliders
- tabs
- counters
- accordions
- hover effects
- sticky elements
- interactions

Convert initialization only where necessary so they work correctly with Elementor.

Ensure scripts also initialize properly after:

- AJAX rendering
- Elementor preview

- Popup loading
- Dynamic content loading

Where applicable, migrate global values into editable settings.

Examples:

# 8. Responsive Behaviour

Current responsive behavior must remain identical.

Desktop

Tablet

Mobile

Large Desktop

Nothing should break after conversion.

---

# 9. Performance

Avoid unnecessary nesting.

Avoid redundant wrappers.

Minimize DOM size.

Load assets only when needed.

Do not introduce unnecessary Elementor widgets.

---

Where possible, convert repeating sections into reusable Elementor Templates.

Examples:

- CTA
- Footer
- Header
- Hero
- Testimonials
- FAQ
- Service Cards
- Team Cards

These should be reusable across pages.

---

# 11. Custom Widgets (If Needed)

If a section cannot be recreated efficiently using native Elementor widgets, create custom Elementor widgets.

Examples:

- Advanced Hero
- Animated Statistics
- SEO Cards
- Timeline
- Process Flow
- Feature Cards

These widgets should expose editable controls instead of relying on hardcoded HTML.

---

# 12. Global Styling

Where appropriate, use Elementor Global Styles for:

- Typography
- Colors
- Buttons
- Form Fields
- Links
- Icons

Maintain consistency with the current design.

---

# 13. Elementor Editor Experience

The editor should be clean and intuitive.

Users should be able to:

- edit headings directly
- replace images
- update buttons
- modify icons
- reorder sections
- duplicate containers
- save templates
- adjust responsive settings

without touching HTML.

---

# 14. Import/Export Compatibility

The converted theme must fully support Elementor's import/export functionality.

When importing the theme into another WordPress installation:

- All pages should import correctly.
- All Elementor templates should be preserved.
- All sections should remain editable.
- Theme settings should remain intact.
- Global styles should be retained.
- Reusable templates should import correctly.
- Dynamic content should remain linked.
- Images should map correctly using the WordPress Media Library.
- Required assets (CSS, JS, fonts, icons, templates) should be included.
- No broken layouts or missing widgets should occur after import.

The imported site should behave exactly like the original without requiring manual reconstruction.

---

# 15. Compatibility

The converted theme should be compatible with:

- Latest WordPress
- Latest Elementor
- Elementor Pro (if installed)
- Future Elementor updates

Follow WordPress coding standards and Elementor development best practices.

---

# Expected Deliverable

The final result should be a fully native Elementor theme where:

- The frontend design is **100% identical** to the existing website.
- No redesign or visual alterations are introduced.
- HTML widgets are replaced with proper Elementor containers and widgets.
- Every editable component is manageable through Elementor.
- Existing CSS and JavaScript continue to function correctly.
- Templates are reusable and maintainable.
- The entire theme can be imported/exported seamlessly with all layouts, templates, settings, assets, and dynamic content preserved.
- Future enhancements can be implemented without restructuring the theme.

The objective is **implementation modernization**, not visual redesign.
